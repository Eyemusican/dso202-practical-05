# Task 2: Why the ConfigMap name is not exactly web-content

Kustomize's configMapGenerator adds a hash of the file's content to the end of the name it's given. So web-content becomes web-content-c66b5fcmdt. This happens because ConfigMaps aren't versioned on their own, if I edited index.html and kept the name web-content, Kubernetes wouldn't notice anything changed, since the name is identical, and the Deployment would keep using its old cached version. By putting a hash of the content into the name, any change to the file produces a new name, so the Deployment (whose volume reference gets rewritten to match) picks up the new ConfigMap automatically. It also means the old ConfigMap is left behind under its old name rather than being overwritten, so a rollback still has something to roll back to.
